# Nata's Kitchen 🍽️

Личная коллекция рецептов: мобильное веб-приложение без сборки (vanilla JS + Firebase Firestore), с распознаванием рецептов по фото/тексту через GPT-4o и автоматическим расчётом калорийности.

## Страницы

| Файл | Назначение |
|---|---|
| `index.html` | Главная: список рецептов, поиск, фильтры по категориям, карточка рецепта (множитель порций, панель КБЖУ), встроенный редактор |
| `add-recipe.html` | «Умный загрузчик»: распознавание рецепта из фото или вставленного текста через GPT-4o, ручная правка, сохранение |
| `nutrition.html` | Админка базы калорийности: сканирует все рецепты, показывает какие ингредиенты без данных КБЖУ, заполняет их через GPT |
| `tools/seed-recipes.html` | Одноразовый скрипт первичной загрузки рецептов (оставлен как архив) |

## Общие модули (`js/`)

| Модуль | Содержимое |
|---|---|
| `js/firebase.js` | Единая инициализация Firebase + реэкспорт функций Firestore |
| `js/constants.js` | Категории (TAGS) и набор эмодзи |
| `js/utils.js` | Экранирование HTML, нормализация имён ингредиентов, slug для id, разбор чисел/дробей (в т.ч. юникод-дроби ½ ⅓ ¾), масштабирование количеств, хранение ключа OpenAI |
| `js/nutrition.js` | Перевод «2 ст. л. / 1 кочан / 3 шт» в граммы, дефолтные веса штучных продуктов, промпт и вызов GPT для КБЖУ, чтение/запись коллекции `nutrition`, разворачивание секций-разделителей в ингредиентах |

⚠️ Страницы используют ES-модули с относительными импортами — приложение нужно открывать по HTTP(S) (GitHub Pages, Firebase Hosting, `npx serve`), а не как локальный файл `file://`.

## Данные (Firestore)

- **`recipes/{slug}`** — `{ id, emoji, title, meta, yield, note, tags[], ingredients[{n, a}], steps[] }`.
  Строка ингредиента, начинающаяся с `—`, считается заголовком секции («— ТЕСТО: Мука» = секция «ТЕСТО» + ингредиент «Мука»).
- **`nutrition/{normalizedName}`** — `{ kcal, protein, fat, carbs, unitG? }` на 100 г; `unitG` — вес одной штуки для штучных продуктов.

## Безопасность — важно

1. **Правила Firestore.** Конфиг Firebase в клиентском коде — это нормально (он публичный по дизайну), но защищать данные должны правила доступа. Файл `firestore.rules` содержит рекомендуемый вариант: чтение всем, запись только владельцу. Его нужно задеплоить вручную (Firebase Console → Firestore → Rules), пока действуют «test mode» правила — базу может изменить кто угодно.
2. **Ключ OpenAI** хранится в `localStorage` и вызовы идут напрямую из браузера. Для личного использования допустимо; для публичного продукта нужен серверный прокси (Cloud Function), чтобы ключ не находился на устройстве пользователя.

## Запуск локально

```bash
npx serve .
# открыть http://localhost:3000
```
