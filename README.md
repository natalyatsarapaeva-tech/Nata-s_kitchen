# Nata's Kitchen 🍽️

Личная коллекция рецептов: мобильное веб-приложение без сборки (vanilla JS + Firebase Firestore), с распознаванием рецептов по фото/тексту через GPT-4o и автоматическим расчётом калорийности.

## Страницы

| Файл | Назначение |
|---|---|
| `index.html` | Главная: список рецептов, поиск, фильтры, карточка рецепта (множитель порций, панель КБЖУ, отметка «приготовил»), встроенный редактор, «🎲 Что приготовить?» (подбор из своих + «🌍 Удиви меня» через GPT/веб-поиск) |
| `add-recipe.html` | «Умный загрузчик»: распознавание рецепта из фото или вставленного текста через GPT-4o, ручная правка, сохранение |
| `nutrition.html` | Админка справочника ингредиентов: сканирует рецепты, заполняет КБЖУ и атрибуты (категория, pantry-staple, хранение) через GPT |
| `tools/migrate-recipes.html` | Миграция рецептов на структурную схему: qty/unit/канонический ингредиент, порции, атрибуты планировщика — GPT + ручная проверка |
| `tools/seed-recipes.html` | Одноразовый скрипт первичной загрузки рецептов (оставлен как архив) |

## Общие модули (`js/`)

| Модуль | Содержимое |
|---|---|
| `js/firebase.js` | Единая инициализация Firebase + реэкспорт функций Firestore |
| `js/constants.js` | Категории (TAGS) и набор эмодзи |
| `js/utils.js` | Экранирование HTML, нормализация имён ингредиентов, slug для id, разбор чисел/дробей (в т.ч. юникод-дроби ½ ⅓ ¾), масштабирование количеств, хранение ключа OpenAI |
| `js/nutrition-core.js` | Чистая логика (без Firebase, тестируется в Node): перевод количеств в граммы, структурные единицы, справочник с синонимами, расчёт КБЖУ рецепта и на порцию, вызовы GPT |
| `js/nutrition.js` | Firestore-обёртки над core: загрузка справочника, чтение/запись документов; реэкспортирует core |
| `js/suggest.js` | «Что приготовить?»: фильтры (приём пищи/время/настроение), скоринг по давности готовки, взвешенный случайный выбор, честное ослабление фильтров, проверка похожести для «Удиви меня» |

## Данные (Firestore)

- **`recipes/{slug}`** — `{ id, emoji, title, meta, yield, servings?, note, tags[], ingredients[], steps[], attrs?, needsReview?[] }`.
  - Строка ингредиента: `{ n, a }` — исходный текст (никогда не разрушается) + структурные поля после миграции: `qty` (число), `unit` (`g|ml|pcs|tbsp|tsp|pinch`), `ing` (канонический ключ справочника), `opt` (по желанию).
  - Строка, начинающаяся с `—`, считается заголовком секции («— ТЕСТО: Мука» = секция «ТЕСТО» + ингредиент «Мука»).
  - `servings` — число порций (для расчёта КБЖУ на порцию).
  - `attrs` — атрибуты планировщика: `{ mealType[], mainProtein, cuisine, activeMin, totalMin, heaviness, spiciness, dietFlags[], kidFriendly }`.
  - `needsReview` — предупреждения миграции, снимаются вручную в `tools/migrate-recipes.html`.
- **`nutrition/{canonicalName}`** — справочник ингредиентов: `{ kcal, protein, fat, carbs, unitG?, aliases?[], category?, isPantryStaple?, perishability?, storage? }` на 100 г; `unitG` — вес одной штуки; `aliases` — синонимы («томат» → «помидор»).

## Безопасность — важно

1. **Правила Firestore.** Конфиг Firebase в клиентском коде — это нормально (он публичный по дизайну), но защищать данные должны правила доступа. Файл `firestore.rules` содержит рекомендуемый вариант: чтение всем, запись только владельцу. Его нужно задеплоить вручную (Firebase Console → Firestore → Rules), пока действуют «test mode» правила — базу может изменить кто угодно.
2. **Ключ OpenAI** хранится в `localStorage` и вызовы идут напрямую из браузера. Для личного использования допустимо; для публичного продукта нужен серверный прокси (Cloud Function), чтобы ключ не находился на устройстве пользователя.
