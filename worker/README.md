# Прокси к OpenAI (Cloudflare Worker)

Держит ключ OpenAI у себя, а браузер пускает по Firebase ID-токену той же
семьи, что уже вошла в приложение. До него каждый вводил свой ключ, и ключ
лежал в `localStorage` — виден в devtools и уезжал вместе с устройством.

Пока адрес Worker'а не прописан в `js/gpt.js`, приложение работает по-старому,
на личных ключах. Никакой промежуточной поломки: включение — одна строка.

## Что проверяется на каждом запросе

| Проверка | Зачем |
|---|---|
| `Origin` из `ALLOWED_ORIGINS` | чужой сайт не дёргает наш прокси из браузера |
| Подпись Firebase ID-токена по ключам Google (`RS256`, JWKS) | токен настоящий, а не набранный руками |
| `iss` / `aud` / `exp` | токен нашего проекта и не протух |
| Почта из `ALLOWED_EMAILS` | **главное**: в Firebase-проекте открыта саморегистрация, так что «просто вошедший» — не свой |
| Частота (20 запросов в минуту на пользователя) | сорвавшийся цикл в отладке не сожжёт бюджет |
| Размер тела ≤ 12 МБ, модель из списка, `max_tokens` ≤ 8000 | прокси умеет ровно то, что нужно приложению |

Ничего из этого не доходит до OpenAI: непрошедшее отваливается на 4xx.

**`ALLOWED_EMAILS` пустой = прокси закрыт для всех.** Это осознанный
fail-closed: забытый список не должен означать открытый доступ к платному
ключу.

## Деплой

```sh
cd worker
npx wrangler login                      # один раз
npx wrangler secret put OPENAI_API_KEY  # вставить ключ, он больше нигде не хранится
```

Впиши почты семьи в `ALLOWED_EMAILS` в `wrangler.toml` и задеплой:

```sh
npx wrangler deploy
```

Wrangler напечатает адрес вида `https://natas-kitchen-gpt.<аккаунт>.workers.dev`.

## Включение в приложении

1. Проверь на живом сайте, ничего не коммитя:
   в консоли браузера `localStorage.gpt_proxy = 'https://natas-kitchen-gpt.<аккаунт>.workers.dev'`,
   перезагрузи и вызови любую GPT-функцию. Ключ спрашивать не должны.
   Убрать: `localStorage.removeItem('gpt_proxy')`.
2. Когда всё работает — впиши тот же адрес в `GPT_PROXY_URL` (`js/gpt.js`) и
   запушь в `main`: GitHub Pages выкатит за минуту, и ключи в браузерах
   больше не нужны.

## Проверка руками

```sh
# без токена — 401
curl -s -X POST https://<worker>/v1/chat/completions \
  -H 'Content-Type: application/json' -d '{"model":"gpt-4o","messages":[]}'
```

Логи: `npx wrangler tail`.

## Что осталось за кадром

- Лимит частоты живёт в памяти изолята: Cloudflare поднимает их несколько, и
  они умирают. Это заслон от срыва цикла, а не строгая квота. Нужна
  строгая — прикрутить KV или Durable Object.
- Учёт расхода по членам семьи не ведётся. Если понадобится — писать `uid`,
  модель и `usage` из ответа в KV/Analytics Engine.
